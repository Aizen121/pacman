# Pac-Man: Ghosts! More ghosts!

> **Work in progress.** The deadline is 2026-10-31. Sections marked **TODO** will be completed as the matching planning task is delivered (task IDs refer to the project planning).

## Description

This project is a remake of Namco's 1980 arcade classic *Pac-Man*, written in Python with object-oriented programming. Graphics use a library restricted to functions that have a MiniLibX equivalent. The player must eat every pacgum in a maze while four ghosts chase them. Super-pacgums (power pellets) briefly turn the tables.

Project goals:
- a complete, playable game with at least 10 levels, autonomous ghosts, a score, lives and a timer for each level
- mazes generated by the **A-Maze-ing** package of another 42 group, used as-is
- a JSON configuration file (with `#` comments) that never crashes the game, even when it is invalid
- a persistent top-10 highscore table
- a cheat mode for peer review
- a packaged build published on itch.io
- a documented project-management approach

```bash

make run       # runs install, then: uv run python pac-man.py config.json
```

Run it from the repository root, because asset paths are relative to it. The game opens full screen, at the size of your screen. To play in a window instead, set `FULLSCREEN = False` in `src/constants.py`.

## Configuration

The game reads one JSON configuration file. Lines whose first non-blank character is `#` are comments and are ignored. Every key is optional, and the default values are exactly the ones shipped in `config.json`.

```
{
    # Highscores are saved in this file
    "highscore_filename": "data/leaderboard.json",
    # Only two levels here: the game adds default levels to reach 10
    "levels": [
        {"width": 15, "height": 15},
        {"width": 20, "height": 20}
    ],
    "lives": 3,
    "pacgum": 42,
    "points_per_pacgum": 10,
    "points_per_super_pacgum": 50,
    "points_per_ghost": 200,
    "seed": 42,
    "level_max_time": 90
}
```

| Key | Type | Default | Allowed values | Meaning |
|---|---|---|---|---|
| `highscore_filename` | string ending in `.json` | `"data/leaderboard.json"` | any path ending in `.json` | File where the top 10 is saved |
| `levels` | list of `{"width": w, "height": h}` | the 10 levels of `config.json` | `w` and `h` from 5 to 50 | Maze size of each level, in cells, in play order |
| `lives` | integer | `3` | 3 to 9 | Lives at the start of the game |
| `pacgum` | integer | `42` | 1 to the number of free cells of the level | Pacgums placed in each level |
| `points_per_pacgum` | integer | `10` | 0 to 10 000 | Points for eating a pacgum |
| `points_per_super_pacgum` | integer | `50` | 0 to 10 000 | Points for eating a super-pacgum |
| `points_per_ghost` | integer | `200` | 0 to 10 000 | Points for eating an edible ghost |
| `seed` | integer | `42` | 1 or more | Seed of the level 1 maze, so level 1 is always the same (later levels are random) |
| `level_max_time` | integer | `90` | 10 to 600 | Time limit of each level, in seconds |

### Error handling

The configuration never crashes the game and never produces a Python traceback. Every correction is reported with a one-line message in the terminal, for example:

```
Config: "lives" = 1 is below the minimum (3), using 3.
Config: unknown key "speed" ignored.
```

| Problem | What the game does |
|---|---|
| Wrong command line (no argument, several arguments, or a file not ending in `.json`) | Prints the usage and exits |
| File missing, unreadable, not valid JSON, or not a JSON object | Uses the whole default configuration |
| Key missing, or value of the wrong type | Uses the default value of that key. Integers must be real JSON integers: `"10"`, `10.5` and `true` are refused |
| Integer outside its allowed range | Uses the nearest allowed value (`"lives": 1` becomes 3) |
| Unknown key | Ignores it |

Levels follow these extra rules:
- An entry that is not `{"width": integer, "height": integer}` is ignored.
- Each dimension is clamped between 5 and 50.
- If fewer than 10 levels remain (the subject requires at least 10), the list is completed with the default levels.
- If `levels` is missing or is not a list, the 10 default levels are used.

Why these limits:
- **Maze size:** the maze package crashes below 2 cells, and 5 cells leave room for the four ghost corners and the player in the center. Above 50 cells, a cell would be smaller than 15 pixels in the 800-pixel-high window.
- **`lives`:** the subject says the player starts with 3 lives, so the minimum is 3.
- **`seed`:** the maze package treats 0 and negative seeds as "random", which would break the fixed level 1.
- **`highscore_filename`:** the `.json` rule prevents the game from overwriting a source file such as `pac-man.py` when it saves scores.
- **Points:** the score must never decrease, so points can't be negative. The upper limit stops absurd scores from overflowing the HUD.

## Highscore

- Highscores are stored as JSON in the file named by `highscore_filename` (`data/leaderboard.json` in the provided config), with the shape `{"leaderboard": [{"name": "...", "score": ...}]}`.
- The top 10 is shown from the main menu (*HIGHSCORES*).
- A player name has 1 to 10 characters (letters, digits and spaces), and a score is a non-negative integer. A score that breaks these rules is refused.
- The top 10 is loaded once at startup and saved each time a score is added, that is at the end of a game.
- A missing file means no score yet; it is created, with its folder, at the first save.
- An unreadable or broken file, or an entry that breaks the rules, is reported on stderr and skipped: the game always starts, and the next save rewrites the file.

## Maze Generation

- Mazes come from the A-Maze-ing package assigned to us: `mazegenerator` 2.1.0 (its metadata lists the author as `ol`), shipped as `mazegenerator-2.1.0-py3-none-any.whl`. We use it **as-is**: `make install` extracts the wheel into `mazegenerator/`, and our code adapts to its interface.
- Each level creates one `MazeGenerator(size=(width, height), seed=...)` with `perfect=False`, which is the package default. This adds loops and removes dead ends, which gives Pac-Man-style corridors.
- The output is a grid `maze[y][x]` of 4-bit wall masks: `1` top, `2` right, `4` bottom, `8` left (a set bit means a wall). Cells equal to `15` are closed and form the "42" pattern in the middle of the maze. The pattern only appears when the maze is at least 14×10.
- Level 1 uses the `seed` from the configuration, so it is always the same maze. Later levels pass the seed `0`, which the package treats as "draw a random maze". We don't draw a random seed ourselves: generating level 1 reseeds Python's global random module with the fixed seed, so a seed drawn from it afterwards would be the same in every game.
- The player starts on the free cell closest to the middle of the maze, because the exact middle can be one of the closed "42" cells.
- If the package raises an error, the game stops with a clear message instead of a traceback (see `Level._generate` in `src/game/level.py`).

## Implementation

- Python 3.12 with pygame, restricted to functions that have a MiniLibX equivalent (pixel put, image put, string put), so shapes are drawn pixel by pixel. pydantic validates the configuration.
- The main loop runs at 60 FPS. Each frame reads input events, updates the current state with the elapsed time `dt`, draws, and flips the display.
- Pixel-by-pixel drawing is slow, so static graphics (sprites, the maze of the current level) are rendered once into off-screen surfaces and copied every frame.
- Pac-Man moves on the grid as a cell plus a progress toward the next cell. He goes 4 cells per second on level 1, and 0.2 more on each following level. He turns at cell centres, remembering a direction pressed too early, and can make a U-turn at any time. Walls are checked with the maze's wall bitmask.
- Pac-Man is drawn by code as a disc minus a mouth wedge, pre-rendered in 12 frames (4 directions × 3 mouth openings). The mouth closes on each cell centre and opens wide halfway, so he chomps once per cell, at his own speed.
- Pac-Man eats a pacgum or a super-pacgum when he arrives on its cell, and scores the points set in the configuration. A level is won once every pacgum and super-pacgum is eaten. The next level then starts with the same score. After the last level, the game goes back to the main menu until the victory screen exists.
- The score, the level number, the time left (m:ss) and the lives are shown left of the maze.
- Each level lasts at most `level_max_time` seconds. The "42" in the middle of the maze is also a gauge of that time: its 18 cells empty from the top, one at a time (every 5 seconds with the default 90). When the time runs out, Pac-Man loses a life and the timer starts again; the pacgums already eaten stay eaten. Mazes smaller than 14×10 have no "42", so only the HUD shows the time.
- Ghosts use the same grid movement as Pac-Man, through a shared `Mover` class. At each crossing, a ghost takes the way whose next cell is closest to its target. Distances are counted along the corridors with a breadth-first search, so ghosts go around walls instead of bumping into them. A ghost never turns back on its own, except in a dead end. Blinky (red) targets Pac-Man's cell. Pinky (pink) targets 4 cells ahead of Pac-Man as the crow flies, as in the arcade game, so it often comes from another side. Inky (cyan) is unpredictable: at half of the crossings it takes a random way, otherwise it chases like Blinky. It draws from its own random generator, because the maze package reseeds Python's global `random` module with the fixed seed of level 1. All of them go at 90 % of his speed.
- Touching a ghost costs a life: Pac-Man respawns in the middle and the ghosts in their corners. With no life left, the game goes back to the main menu until the game-over screen exists.
- A super-pacgum makes the ghosts edible for 6 seconds: they turn blue, flash white in their last 2 seconds, and run away at half speed, taking the way farthest from Pac-Man (the same breadth-first search, with the largest distance instead of the smallest). Eating one scores `points_per_ghost`. Its eyes then go back to its corner at twice its speed and wait there, and the ghost revives once 5 seconds have passed since it was eaten.
- The visual identity is "arcade neon": night-blue background, neon-blue walls, cream "42" cells, peach pacgums and amber titles. The palette is defined in `src/constants.py`. Every position, font and icon is computed from the size of the screen, and the main menu, the BACK buttons and the menus react to the mouse.
- Every maze fits the window. Cells are at most 50 pixels and shrink for big mazes (17 pixels for 42×42). The maze is centred right of the HUD, and its walls and sprites are redrawn at that size. Images are never scaled, because MiniLibX has no equivalent.

## General Software Architecture

```
pac-man.py ─ Pacman            application, state machine and main loop
   ├── Config                  src/parser.py         validated configuration (pydantic)
   ├── Scores                  src/game/scores.py    highscore file
   ├── GUI                     src/gui.py            all rendering
   └── Gameplay                src/game/gameplay.py  one game session, created on START
         └── Level             src/game/level.py     one level: maze, pacgums, characters
               ├── MazeGenerator   mazegenerator/    external A-Maze-ing package
               ├── Player          src/player.py     Pac-Man, moved by the keyboard
               └── Ghost           src/ghost.py      chases a target (BFS in src/pathfinding.py)

Player and Ghost both extend Mover (src/mover.py): movement on the grid.
```
